손님이 많은 시간 비어 있는 시간 (데드타임) 필잇으로 채운 모임

공간을 빌리는 쪽도, 빌려주는 쪽도 번거로운 구조입니다

서울의 대학생·20대 모임 주최자가 워크샵, 선배와의 만남, 스터디·소모임 등을 위해 공간을 빌릴 때 반복되는 상황입니다.

빌리는 사람 (모임 주최자)

  1. 네이버 지도에서 '주차 가능 식당', '대형 카페' 등 검색수용 인원은 어림짐작으로 확인
  2. 예약 버튼이 없으면 전화로 대관 문의대관 특화 매장이 아니면 대부분 예약 버튼 없음
  3. 여러 매장에 같은 과정 반복매장별 특징·비용을 메모장 등에 따로 정리한 뒤, 다시 전화해 예약

결과: 최선안 비교가 어려워 타협 반복

빌려주는 사람 (매장)

  1. 대여 문의 전화 응대
  2. 책임자가 아니면 전화를 돌리고 또 돌림
  3. 정해진 기준이 없어 문의글 반복 접수가격·조건 기준 부재
  4. 매장 운영 비효율로 이어짐

단, 빈 시간 임대 문의를 매장이 반긴 사례 확인 (지인 경험) → 데드타임 수익 수요 존재

필잇: 한 곳에 정리

빌리는 사람
  • 목적·인원·시간·위치 입력
  • 조건에 맞는 공간 큐레이션
  • 고정 가격으로 바로 예약·결제
빌려주는 사람
  • 가격·조건을 정해 등록
  • 전화 응대 없이 예약 접수
  • 예약 관리 기능 제공

빌리는 사람도 빌려주는 사람도 효율적으로 계약하고, 소비자는 더 빠르고 쉽게 선택할 수 있습니다.

비슷해 보이는 서비스는 있지만, 운영 중인 매장의 빈 시간을 다루는 곳은 없습니다

기존 서비스를 앱에서 직접 확인해 정리했습니다.

서비스한계
스페이스클라우드·아워플레이스
  • 대여용 공간과 임대 수요자를 잇는 플랫폼
  • 실제 운영 중인 매장과 무관
여기어때 공간대여
  • 영업 종료 후 매장 전체를 대관하는 방식
  • 숙박 중심 앱의 부가 서비스 → 공간 큐레이션 부실
  • 운영 중인 매장과의 연결 구조 없음
덕플레이스 등 생일카페 플랫폼
  • 팬덤 생일카페라는 니치(좁은 틈새) 목적에 한정
네이버 예약
  • 인원수 기반 단순 예약 중심
  • 목적 기반 큐레이션 없음

운영 중인 실제 매장의 유휴 시간을 목적 기반으로 예약할 수 있는 전용 플랫폼은 현재 비어 있습니다.

한 줄이면 됩니다. 나머지는 필잇이 합니다

AI는 말을 이해하고 이유를 설명하는 일을, 로직(정해진 규칙에 따른 처리)은 시간·인원 확인과 예약 관리처럼 정확해야 하는 일을 맡도록 나눠 설계했습니다.

  1. 1

    입력: 자연어 한 줄

    • 목적·인원·시간·지역을 한 문장으로 입력 (드롭다운 입력 대체)
    • Claude API(Anthropic의 AI를 서비스에 붙이는 연결 통로)가 문장을 항목별로 구조화
    AI
  2. 2

    매칭 결과: 지도 + 추천 카드

    • 시간대 겹침·수용 인원·위치 반경 필터링은 데이터베이스 조회로 처리
    • 후보별 "왜 이 매장이 맞는지" 추천 이유를 문장으로 생성
    로직 · 필터링AI · 추천 이유
  3. 3

    상세 페이지

    • 매장 정보·사진·캘린더 형태의 예약 가능 슬롯(시간 칸) 제공
    • 슬롯 관리는 캘린더 API가 담당
    로직 · 캘린더 API
  4. 4

    예약 확정

    • 시간 선택 → 결제 → 확정
    • 확정 메시지를 매장 분위기에 맞게 AI가 개인화 (선택 기능)
    AI · 선택

공간 수요자 (모임 주최자)

  • 소규모 모임을 열고 싶지만 공간 구하기가 번거로운 20~30대
  • 정기 모임·스터디·클래스를 운영하는 커뮤니티 리더
  • 합리적인 가격의 프라이빗 공간이 필요한 소규모 행사 기획자

공간 공급자 (매장 운영자)

  • 평일 낮·오전 등 데드타임 매출 공백이 있는 서울의 카페·식당·바
  • 추가 수익은 원하지만 복잡한 대관 관리는 부담스러운 1인 운영 매장
  • 신규 고객 유입이 필요한 골목 상권 매장
